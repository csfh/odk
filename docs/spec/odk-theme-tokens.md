# ODK theme tokens, version 1

Normative. This spec says what ODK reads from Omarchy and where each of ADR 0040's layers is specified. It must not change a decision recorded in an ADR; if it needs to, write a new ADR first. Where the two disagree, the ADR wins.

Components (ADR 0027) use only tokens, never an Omarchy key name. Only colours, the user's text size, Omarchy's font and the user's own request for reduced motion come from Omarchy (ADR 0043, ADR 0046); every size, width and duration is ODK's own, and the text size scales the sizes (ADR 0035, ADR 0043). `odk-theme` reads two files in `~/.local/state/omarchy/current/theme/` (`docs/checks.md`) and, beside them, the user's own:

| File | What is read |
|---|---|
| a theme's `colors.toml` | the palette, and nothing else of the theme's colours: `docs/spec/odk-source-palette.md`. Everything else is made from it |
| a theme's `shell.toml` | `[font] base-size`, the user's text size when the user's own file has none (ADR 0043). It must be TOML, or the theme is refused (ADR 0041); nothing else in it is read, the `[controls]` colours included (ADR 0047) |
| the user's `~/.config/omarchy/shell.toml` | `[font] base-size`, which wins over the theme's, and `[motion] reduced`, which counts only when the compositor does not say (ADR 0043, ADR 0046, ADR 0048). Never an error |
| Hyprland's IPC socket, `$XDG_RUNTIME_DIR/hypr/<instance>/.socket.sock` and `.socket2.sock` | `animations:enabled`, asked, and its reloads followed: false is the user's request for reduced motion (ADR 0048). Only the followed theme's manager asks (`ThemeManager::current`); a sandbox never reaches it |

The tokens are the four layers of ADR 0040, each made from the one above and specified on its own:

| Layer | Spec | Reached through |
|---|---|---|
| Source | `docs/spec/odk-source-palette.md` | `odk::ui::theme_snapshot().palette`, only for code that must show the palette |
| Semantic | `docs/spec/odk-semantic-tokens.md` | `odk::ui::theme_snapshot().semantic` |
| Component | `docs/spec/odk-component-tokens.md` | `odk::ui::components()` |
| Foundation | `docs/spec/odk-foundation-tokens.md` | `odk::ui::foundation()` |

## The removed tokens

`odk_theme::Tokens` was the flat token set of ADR 0030 and ADR 0035: surface, text, accent, status, border, control, space, font, radius and motion. It was kept while components moved onto the layers, and ADR 0047 removed it (plan step 9, 2026-10-24). Nothing drew it but `root()`, `Space` and the `Shell`. What replaces each:

| Was | Now |
|---|---|
| `odk::ui::tokens()` | `theme_snapshot()` for colours, `foundation()` for sizes and durations, `components()` for a component's style |
| `surface.base`, `text.primary` | `semantic.surface.canvas`, `semantic.text.primary`. The same colours, except `text.primary` in rose-pine, where the resolver's contrast-checked colour is two steps darker |
| `surface.raised`, `sunken`, `scrim`; `text.muted`, `disabled`; `border`, `control`; `accent`; `status` | `semantic.surface`, `semantic.text`, `semantic.border` and the roles' treatments (`Role` at an `Emphasis` and a `State`), through `components()` |
| `space.xs`, `sm`, `md`, `lg`, `xl` | `Space::Xs` to `Xl`, which read `foundation().spacing` `s1`, `s2`, `s3`, `s4` and `s6`: the same 4, 8, 12, 16 and 24 px at 12 px text, rounded the same way at every other text size |
| `font.*` | `foundation().typography`, by type role |
| `radius.*` (0 px), `border.width` | `foundation().geometry` (`corner_radius`, `border_width`) |
| `motion.*` | `foundation().motion` (`fast`, `normal`, `cycle`, `hover_open`, `hover_close`, `toast`, `reduced`) |
| `Tokens::from_toml`, `from_palette`, `load_dir`, `load_current` | `ThemeSnapshot::from_toml`, `ThemeManager` |
| `ThemeSnapshot::tokens` | `ThemeSnapshot::semantic`, `palette`, `text` and `reduced_motion` |
| `odk::ui::Variant`, `Button::variant(Variant::X)` | `ButtonVariant::Primary`, `Secondary` or `Ghost` |
| `Badge::variant(Variant::Primary)`, `Secondary`, `Ghost` | `Badge::role(Role::Accent).emphasis(Emphasis::Solid)`; the default; `Badge::appearance(BadgeAppearance::new(Role::Neutral, Emphasis::Subtle).outlined())` (`Role` is `odk::theme::semantic::Role`, not accessibility's) |

`Tone` stays: it is how an application names a status, and it maps onto `Role`.

## Missing and unusual values

`colors.toml` must define `mode` (`"dark"` or `"light"`), `background`, `lighter_background`, `dark_background`, `foreground`, `muted`, `accent`, `red`, `yellow`, `green` and `blue`, each a `#RRGGBB` or `#RRGGBBAA` colour. A missing or malformed key, required or one of the optional keys of `docs/spec/odk-source-palette.md`, is an error that names it, and `odk-theme` never fills a key in; when no theme can be loaded at all, the application draws the emergency palette (ADR 0041). Every stock Omarchy theme defines all of them. Themes generated by Aether write short names such as `lighter_bg` and `dark_bg` instead, so `odk-theme` reads the eight short names Omarchy's own resolver reads (listed in that spec) when the long name is absent; if both are present the long name wins, and a theme with neither is still an error that names the long key.

A theme's `shell.toml` is optional. When it is missing, or has no `[font] base-size`, the text size is the user's, or 12 px. A theme's `shell.toml` that is not TOML is an error that names the file, and the theme is refused like any that cannot be loaded.

## Checked and not yet checked
