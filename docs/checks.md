## Done

- Rune in place of GPUI, on the development machine on 2026-11-06 (`spikes/rune-ui`; ADR 0004, ADR 0027 and ADR 0029 are unchanged, since nothing is decided). Rune is `github.com/anomalyco/rune` at `dev` rev `7ead7d6`: created 2026-10-22, version 0.0.1, MIT, git only, no pull requests taken. The spike draws a `Button`, a `Select` and an `Input` from stand-in `odkd` values, with Rune's own elements and none of `rune-kit`.
  - Dependencies: with default features off and `accessibility` on, Rune is 253 crates against `odk-ui`'s 523, and 64 of its crate names are not in the workspace (wgpu, winit, parley, AccessKit and AT-SPI, and Rune's own). Swapping it for GPUI would drop GPUI's tree. `accesskit_unix` pulls in `zbus` even with Rune's `dbus` feature off. It builds against `libxkbcommon` and `wayland`, which a stock Omarchy has.
  - Renderer: under `tools/headless-shot`, `RUNE_GPU_LOG=1` reported wgpu on Vulkan, "AMD Radeon 8060S Graphics (RADV STRIX_HALO)", the compositor's GPU. It drew no title bar of its own, and real Wayland keys (Tab Tab Down) opened the `Select`. `tools/idle-cpu` gave 0.0% idle. When the headless sway stopped, the program panicked (`run: Exit Failure: 1`, `app.rs:469`) after "Broken pipe" on the Wayland socket, so losing the compositor is a crash, not an exit. Hyprland itself was not tried, since that would mean a window on the owner's desktop.
  - What Omarchy gives: colours and the text size are only data a view draws with, and the 18 px text size made the button half as tall again as 12 px. `cx.reduced_motion(on)` in the view overrides the host on every commit, so `odkd`'s answer wins over what Rune reads itself on Linux (KDE's `kdeglobals`, GNOME's GSettings through a `dlopen` of `libgio`). Fonts are the gap. Rune finds system fonts only for its monospace slot (fontconfig's `monospace`, which is Omarchy's JetBrainsMono Nerd Font here, so the spike draws in it). `Runtime::set_font_families` (`runtime/font_families.rs`) switches the sans and mono slots while running, but only among families Rune has loaded. Rune's collection is built with `system_fonts: false` (`text.rs`). The spike's test names families in a headless runtime and measures a line: naming Inter, which Rune bundles, keeps its width (233), while C059 and JetBrainsMono Nerd Font, both installed, measure the same as a family that does not exist (230). So any family other than fontconfig's `monospace` has to be handed over as `&'static` bytes in `AppSpec::fonts` before the window opens. A font `odkd` names would be read and leaked by ODK at startup, and a change of it while running needs Rune to load fonts at run time, which it has no public API for. `odkd` names Omarchy's font by the same question, `fc-match monospace` (`crates/odkd/src/read.rs`), so outside the sandbox Rune's monospace slot is Omarchy's font. Rune asks once per process (a `OnceLock` around a run of `fc-match` in `text/system_fonts.rs`), so a font changed with `omarchy-font-set` while an application runs is not followed. Inside the sandbox `~/.config/fontconfig` is not shown (`sandbox/plan.rs` tests that), so `fc-match` there answers with the system's default monospace. That is JetBrainsMono Nerd Font on a stock Omarchy (`ttf-jetbrains-mono-nerd-basic`, the same answer with `$HOME` emptied), but not the user's choice once they pick another, and a font under `~/.local/share/fonts` is not visible at all.
  - Keys: Rune presses a focused control on Space's press and never presses a button on Enter. ODK presses on Enter or Space's release (`docs/spec/odk-interaction.md`). The spike's button takes both keys in `El::on_key`, which runs before Rune's own activation, and presses in `El::on_key_up`; its test failed when the key-down handler was taken away. But it presses on any release while it has focus, so a key whose press moved focus onto it (Rune's own Escape on a modal, say) would press it on release. Pressing only for a press it saw needs a held flag, and in Rune that flag lives in the application's state. Escape, focus going back to the trigger, a press outside, arrows and typing in the field all worked with Rune's own focus, modal and editor. On Linux, Tab visits every control.
  - Accessibility: `Runtime::accessibility_json` gave the button, a `combo-box` with its value, and the `text-input` with its name and placeholder. But `accesskit_unix` 0.24.1 opens the session bus before it reads `AT_SPI_BUS_ADDRESS`, and the sandbox refuses the session bus (ADR 0012, `docs/spec/sandbox-baseline.md`), so a sandboxed application would give Orca nothing. Without a bus it stays quiet and does not crash (every headless run above had none). A screen reader would need its own sandbox decision.
  - Overlays inside a modal (the case ADR 0039 lifts to a host, since GPUI cannot nest `deferred`): a `Select` inside a `Dialog` opened under its trigger, chose on a press, and Escape closed the listbox, gave focus back to its trigger and left the dialog open. A second Escape closed the dialog and gave focus back to its opener, and Tab stayed inside it. The listbox was still lifted by hand: the dialog collects its select's popup and scrim and adds them to the root's list of layers after itself, as `rune_kit::root` draws them, so ODK would still need a root that draws a layer list, though no host entity. With the popup there, Rune's stack of modals did the nesting; the test failed when the listbox's `modal` was taken away. A popup anchored inside the dialog's own subtree was not tried. Each `Select` reaches its own part of the application's state through an accessor (`fn(&mut State) -> &mut Pick`), since Rune's handlers get the whole state.
  - IME through `Runtime::ime`: pre-edit was held in `TextEdit::preedit` and not inserted, and a commit inserted the text and ended it. That is Rune's own path from winit; fcitx5 on Hyprland and the candidate window's place were not tried.
  - Frame cost, `cargo test --release frame_cost`, three runs at a load of about 2: a scrolling page of 100 rows of a button, a select and a field (300 controls) took 8 to 9 ms for its first frame, 1.4 ms (median) and 2.3 ms (worst of 20) to rebuild after a change, and 0.19 ms for a frame with nothing changed. That is the view, layout and Rune's real text shaping, without the GPU's paint, so it cannot be compared with `cargo bench -p odk-ui`, whose text shaping is a stand-in.
  - Not supported: the primary selection. Rune's source names no primary selection (`primary selection`, `primary_selection`, `zwp_primary`, `LinuxClipboardKind`, `Primary` as a clipboard kind); its one use of `arboard`'s Linux extension (`clipboard/native.rs`) is `exclude_from_history`, and a middle press reaches only canvas handlers (`input/canvas_input.rs`), never a text field. Rune's issues name nothing about finding a system font by family either (#45, fallback fonts on NixOS, is closed).
  - Not shown: drag, virtualised rows, and Hyprland itself. Rune's model is a view function of one state (`fn(&S, &mut Cx<S>) -> El`), so a component's transient state, such as a held key or an open menu, lives in the application's state or in Rune's runtime, not in an entity of its own as with GPUI. Moving `odk-ui` would be a rewrite of its components and of the checklist tests, which run on GPUI's test platform.
